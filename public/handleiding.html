Darwin — Handleiding

Volledige handleiding voor het Darwin AI platform. Laatst bijgewerkt: juni 2025.

Branching & Deployment

Darwin gebruikt een develop → main branching strategy. Elke wijziging gaat eerst naar develop, wordt daar getest, en pas daarna naar main gemerged.

Branches

BranchDoelNetlify URL
developActieve ontwikkeling & testendevelop--jouwsite.netlify.app (staging)
mainProductiejouwsite.netlify.app (productie)
Ja, precies: een commit/merge naar develop herbouwt de staging-omgeving en is daar actueel. Een commit/merge naar main herbouwt de productie-omgeving en is daar actueel.

Elke branch leeft op zijn eigen URL met zijn eigen env-variabelen, en draait pas opnieuw wanneer er iets naar díe branch gepusht wordt. Een commit naar develop raakt productie dus niet, en andersom.

Eén ding om in je achterhoofd te houden: ze lopen onafhankelijk. Als je iets naar develop pusht maar nooit doormerge naar main, blijft productie gewoon op de oude versie staan — wat precies de bedoeling is. Productie verandert alleen als er iets in main landt.

Workflow per feature/fix

  1. Branch vanaf develop: 
    git checkout develop
git pull origin develop
git checkout -b feat/<scope>-<korte-beschrijving>
  2. Committen & pushen naar je feature-branch
  3. Open een Pull Request naar develop
  4. Test op develop (Netlify preview-deploy of lokaal):
    • npx tsc --noEmit slaagt
    • npm run build slaagt
    • Pre-commit hook (fitness checks + gitleaks) groen
    • Happy-path handmatig getest in browser
  5. Pas daarna: PR van develop → main

Hotfix

  1. Branch hotfix/<scope>-<beschrijving> vanaf main
  2. Fix, test, commit
  3. PR naar zowel main als develop
NOOIT direct naar main committen of pushen. Altijd via develop.

Netlify dashboard configureren

In de Netlify dashboard: Site settings → Build & deploy → Branches:

  • main → productie-deploy (gepubliceerd)
  • develop → preview-deploy (niet gepubliceerd, alleen voor testen)

Omgeving instellen

Vereisten

  • Node.js 20+
  • npm
  • Supabase project (PostgreSQL + Auth + Storage + Edge Functions)
  • n8n (self-hosted via Docker, voor documentverwerking)

  2. Maak een organisatie aan: 
    INSERT INTO organizations (name) VALUES ('Mijn Organisatie');

Command Center

De Command Center is het startpoud na inloggen. Het toont:

  • Aantal assistenten in je organisatie
  • Aantal kennisbronnen
  • Aantal teamleden

Assistenten

Beheer je AI-assistenten en chat met ze. Elke assistent is gekoppeld aan een n8n-webhook (RAG-chat) en optioneel aan één of meer kennisbronnen.

Aanmaken & bewerken

  1. Ga naar Assistenten in de sidebar
  2. Klik + Nieuwe assistent
  3. Vul in: naam, type (chat), beschrijving
  4. Selecteer de kennisbronnen die deze assistent mag gebruiken
  5. Vink Actief aan (of uit om te deactiveren)
  6. Klik Opslaan

Bewerken: klik op het potlood-icoon naast een assistent. Verwijderen: klik op de prullenbak in het bewerkingsdialoog (verwijdert ook alle gekoppelde conversaties en kennisbronkoppelingen).

Chatten (stateless)

Klik Chat op een assistent-kaart om het chatvenster te openen. Het chatvenster is stateless: bij elke openening start een nieuwe conversatie. Eerdere berichten zie je niet terug in het chatvenster — die zijn opgeslagen en terug te lezen via het Geschiedenis-tabblad.

Bij elke gestuurde vraag:

  1. Het bericht wordt opgeslagen in de Supabase messages-tabel
  2. Darwin roept de n8n-webhook aan met de conversatie-historie
  3. Het antwoord verschijnt in de chat en wordt opgeslagen
  4. Bronnen (kennisfragmenten) zijn uitklapbaar per antwoord

Na afloop kun je duimpjes omhoog/omlaag geven. Bij een duimpje omlaag wordt gevraagd om tekstuele feedback.

Geschiedenis

Het Geschiedenis-tabblad toont alle eerdere chat-runs. Per run zie je:

  • Naam en icon van de assistent
  • Titel van de conversatie
  • Datum/tijd

Filteren

Rechtsboven staat een filter-dropdown waarmee je runs van één specifieke assistent kunt tonen.

Berichten teruglezen

Klik op een run in de lijst om een rechtse drawer te openen met alle berichten (read-only), inclusief uitklapbare bronnen. Sluiten met het X-icoon.

Roadmap

Het Roadmap-tabblad toont de product-roadmap met features die in ontwikkeling zijn of gepland staan. Gebruikers kunnen stemmen op features die zij belangrijk vinden — dit biedt transparantie over de ontwikkelrichting.

Statussen

In ontwikkelingAmberWordt momenteel gebouwd

Filteren

Bovenaan de pagina staan filter-tabs: Alle / In overweging / Gepland / In ontwikkeling / Verzonden.

Stemmen (upvote / downvote)

Elke feature-rij heeft twee pijl-knoppen:

  • Pijl omhoog (groen bij actief) — upvote (+1)
  • Pijl omlaag (rood bij actief) — downvote (−1)

De lijst is aflopend gesorteerd op score (upvotes − downvotes). De score is zichtbaar voor iedereen. Stem-gedrag:

  • Nog niet gestemd + klik omhoog → upvote (+1)
  • Al upvoted + klik omhoog → stem verwijderd (toggle uit)
  • Al upvoted + klik omlaag → wissel naar downvote (−2 verschil)
  • Eéén stem per gebruiker per feature (UNIQUE constraint in database)

De UI updatet direct (optimistic update); bij een fout wordt de stem teruggedraaid met een foutmelding.

Feature request indienen

Heb je een idee voor een nieuwe feature? Dien een request in:

  1. Klik Feature request rechtsboven
  2. Vul in:
    • Titel (verplicht) — korte beschrijving van je idee
    • Beschrijving (verplicht) — wat moet de feature doen
    • Waarom heb je dit nodig? (optioneel) — motivatie
  3. Klik Verzenden

Het request wordt opgeslagen in Supabase en direct per e-mail naar jaap@jaaphoeve.com gestuurd via Resend. Je krijgt geen publieke status terug te zien — de admin beoordeelt elk request en promoveert het (al dan niet) naar een stem-baar roadmap-item.

Kennisbronnen

Kennisbronnen zijn collecties documenten die assistenten kunnen raadplegen via RAG (Retrieval-Augmented Generation). Elke kennisbron heeft een eigen vector-collection in de vector database.

1. Nieuwe kennisbron aanmaken

  1. Ga naar Kennisbronnen in de sidebar
  2. Klik op + Nieuwe kennisbron
  3. Vul een naam in (bijv. "HR Documenten") en optioneel een beschrijving
  4. Klik Opslaan

2. Documenten uploaden

  1. Klik op een kennisbron om de detailweergave te openen
  2. In de Documenten tab: klik op het upload-gebied of sleep een bestand
  3. Toegestane typen: PDF, TXT, DOCX
  4. Het document verschijnt in de lijst met status Verwerken

Bij de upload stuurt Darwin een webhook naar n8n (zie N8N Webhook sectie). n8n downloadt het bestand, chunkt+embed het in de vector database, en werkt de status bij naar Ready. Bij een fout wordt de status Error.

3. Documenten verwijderen

Klik op het prullenbak-icoon naast een document om het permanent te verwijderen uit zowel Supabase Storage als de database. n8n krijgt een delete-webhook om de vectors op te ruimen.

Team

Het Team-tabblad (alleen voor admins) toont alle leden van je organisatie en openstaande uitnodigingen.

Lid uitnodigen

  1. Klik + Nodig uit
  2. Vul e-mailadres en rol (Lid of Admin) in
  3. De uitnodiging wordt aangemaakt; de edge function invite-user maakt het account aan
  4. De genodigde kan inloggen met het opgegeven e-mailadres

Uitnodiging intrekken

Klik op het prullenbak-icoon naast een openstaande uitnodiging om deze in te trekken.

Instellingen

Het Instellingen-tabblad (alleen voor admins) bevat tenant-beheer en flow-configuraties. Hier kun je:

  • Nieuwe organisaties/tenants aanmaken (via de create-tenant edge function)
  • n8n-webhook URLs en tokens configureren per flow-type (RAG chat, document processing)

N8N Webhook instellen

Wat stuurt Darwin naar N8N?

Bij elke documentactie stuurt Darwin een POST naar de webhook URL:

Upload (action: index)

{
  "action": "index",
  "tenant_id": "uuid-van-organisatie",
  "document_id": "uuid-van-document",
  "document_name": "handleiding.pdf",
  "document_type": "pdf",
  "file_path": "org-uuid/kb-uuid/doc-uuid.pdf",
  "download_url": "https://xxx.supabase.co/storage/v1/object/sign/..."
}

Verwijdering (action: delete)

{
  "action": "delete",
  "tenant_id": "uuid-van-organisatie",
  "document_id": "uuid-van-document",
  "document_name": "handleiding.pdf",
  "document_type": "pdf",
  "file_path": "org-uuid/kb-uuid/doc-uuid.pdf",
  "download_url": ""
}
  • download_url is 15 minuten geldig bij index. n8n moet het document binnen die tijd downloaden.
  • file_path is het pad in Supabase Storage. Gebruik dit om het bestand na verwerking te verwijderen.
  • Bij delete is download_url leeg omdat het bestand al uit Storage is verwijderd.

Actions in de webhook payload

ActionWanneerBeschrijving
indexBestand geüpload via UIn8n downloadt, chunkt+embed, werkt status bij, verwijdert bestand uit Storage
modify(placeholder, komt later)Nog niet in gebruik
deleteBestand verwijderd via UIn8n ruimt vectors op; bestand is al uit Storage verwijderd

Stap 1 — Webhook URL instellen in Darwin

Zet in .env.local:

VITE_N8N_DOCUMENT_WEBHOOK=https://jouw-n8n-domein/webhook/documents

Stap 2 — N8N workflow aanmaken

  1. Open n8n, maak een nieuwe workflow
  2. Voeg een Webhook trigger node toe:
    • HTTP Method: POST
    • Path: /documents
    • Response Mode: Last Node
  3. Activeer de workflow — je ziet nu de Production URL
  4. Kopieer die URL naar .env.local als VITE_N8N_DOCUMENT_WEBHOOK

Stap 3 — Supabase credentials in n8n

n8n heeft de service role key nodig om documenten te downloaden en statussen up te daten:

VariabeleWaar te vinden
SUPABASE_URLSupabase Dashboard → Settings → API → Project URL
SUPABASE_SERVICE_ROLE_KEYSupabase Dashboard → Settings → API → service_role

Zet deze als n8n Credentials (type: Supabase) of als environment variables in je n8n Docker container.

Stap 4 — N8N flow logica

Webhook → Switch (action) → [index] Download → Chunk + Embed → Update status → Delete file from Storage
                                → [delete] Cleanup vectors

Index flow (bestand geüpload)

  1. Webhook node vangt de POST → geeft action, tenant_id, document_id, document_name, document_type, file_path, download_url
  2. Switch node op action: index → verwerken, delete → opruimen
  3. HTTP Request (GET {download_url}) → downloadt het bestand (binnen 15 min!)
  4. Chunk + Embed naar je vector database (bijv. via LangChain node of custom code)
  5. Supabase node → UPDATE knowledge_base_documents SET status = 'ready' WHERE id = '{document_id}'
  6. HTTP Request → verwijdert het bestand uit Storage na verwerking:
    • Method: DELETE
    • URL: {{ $env.SUPABASE_URL }}/storage/v1/object/knowledge-documents/{{ $json.file_path }}
    • Header: Authorization: Bearer {{ $env.SUPABASE_SERVICE_ROLE_KEY }}
  7. Supabase node → UPDATE knowledge_base_documents SET file_path = NULL WHERE id = '{document_id}'

Bij fouten in stap 4: zet status op error.

Delete flow (bestand verwijderd via UI)

  1. Gebruik het document_id om de vectors uit je vector database te verwijderen
  2. Het bestand is al uit Storage verwijderd door Darwin — geen extra actie nodig

N8N testen

  1. Start Darwin: npm run dev
  2. Upload een PDF naar een kennisbron
  3. Open n8n → Executions → je ziet een nieuwe webhook call met de payload
  4. Controleer of de flow het document correct verwerkt en het bestand uit Storage verwijdert

Edge Functions

Darwin gebruikt Supabase Edge Functions (Deno/TypeScript) voor server-side operaties die de service role key nodig hebben. Deze draaien op Supabase's servers en zijn niet in de browser-bundle.

FunctionPadDoel
create-tenantsupabase/functions/create-tenantNieuwe organisatie + admin-user aanmaken
invite-usersupabase/functions/invite-userLid uitnodigen per e-mail
send-feature-requestsupabase/functions/send-feature-requestFeature request opslaan + e-mail naar jaap@jaaphoeve.com via Resend

create-tenant

Maakt een nieuwe organisatie en een admin-gebruiker aan. Wordt aangeroepen vanuit de Instellingen-pagina (admins only).

Secrets: SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY (automatisch geïnjecteerd door Supabase).

invite-user

Maakt een nieuw auth-account aan voor een uitgenodigd teamlid en koppelt dit aan de organisatie. Wordt aangeroepen vanuit de Team-pagina (admins only).

Secrets: SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY (automatisch geïnjecteerd).

send-feature-request

Ontvangt een feature request van een ingelogde gebruiker, slaat deze op in de feature_requests-tabel, en stuurt een notificatie-e-mail naar jaap@jaaphoeve.com via de Resend API.

Secrets:

SecretBeschrijvingWaar instellen
SUPABASE_URLSupabase project URLAutomatisch geïnjecteerd
SUPABASE_SERVICE_ROLE_KEYService role key (bypasses RLS)Automatisch geïnjecteerd
RESEND_API_KEYResend API key (re_xxx)Supabase Dashboard → Edge Functions → Secrets — handmatig toevoegen

Resend domein: het from-adres Darwin <noreply@jaaphoeve.com> vereist dat jaaphoeve.com is geverifieerd in Resend (DNS-records toevoegen).

PostHog Analytics

Darwin gebruikt PostHog (EU Cloud) voor product analytics. De scope is bewust beperkt tot pageviews en custom events — geen session replay, feature flags of A/B-testing.

Configuratie

VariabeleWaarde
VITE_PUBLIC_POSTHOG_KEYPostHog project key (phc_xxx)
VITE_PUBLIC_POSTHOG_HOSThttps://eu.i.posthog.com (EU Cloud — NOOIT US)
Netlify: deze twee variabelen MOETEN ook in de Netlify dashboard → Site settings → Environment variables staan. Vite inlinet VITE_-vars at build time — zonder deze waarden werkt de productie/staging-build niet.

Init-config (in src/lib/posthog.tsx)

  • defaults: '2025-05-24' → capture_pageview defaultt naar 'history_change' (vangt SPA route-changes)
  • capture_pageleave: true
  • person_profiles: 'identified_only' → géén anonieme profielen (GDPR + kosten)
  • autocapture: false → scope beperkt tot pageviews + custom events
  • disable_session_recording: true

Custom events

User identificatie

PostHog-identiteit is gekoppeld aan de Supabase-auth-sessie: posthog.identify(user.id) bij SIGNED_IN / INITIAL_SESSION, posthog.reset() bij SIGNED_OUT. Alleen de Supabase UUID wordt gebruikt als distinct_id — géén e-mailadres of andere PII.

Resend (e-mail)

Resend is de e-maildienst voor feature-request notificaties. Darwin gebruikt de Resend REST API (POST https://api.resend.com/emails) direct vanuit de send-feature-request edge function.

Setup

  1. Maak een account aan op https://resend.com
  2. Verifieer domein jaaphoeve.com → voeg de DNS-records toe die Resend aangeeft (SPF, DKIM, DMARC)
  3. Maak een API-key aan (re_xxx)
  4. Voeg toe als Supabase secret: RESEND_API_KEY in Supabase Dashboard → Edge Functions → Secrets
From-adres: Darwin <noreply@jaaphoeve.com> vereist dat jaaphoeve.com is geverifieerd in Resend. Zonder geverifieerd domein weigert Resend de e-mail te versturen.
