# Supabase — knowledge (bevestigd)

Feiten en patronen uit Darwinsessies. Bron: feature 009-secure-n8n-proxy (rollout 2026-10-14).

- **Edge Function-secrets**: `SUPABASE_URL`, `SUPABASE_ANON_KEY` en `SUPABASE_SERVICE_ROLE_KEY` zijn platform-defaults — automatisch geïnjecteerd in elke Edge Function en altijd correct. Alleen custom secrets (zoals `ALLOWED_ORIGINS`) moet je handmatig zetten. De Darwin-functies lezen `VITE_`-varianten eerst met fallback op deze defaults (commit `7509967`).
- **Edge gateway vs. functie**: met `verify_jwt` (standaard bij deploy) valideert de gateway de `Authorization`-header vóór de functiecode draait. Gateway-fouten hebben eigen codes: `UNAUTHORIZED_INVALID_JWT_FORMAT` (geen JWT-opbouw) en `UNAUTHORIZED_ASYMMETRIC_JWT` (handtekening/expiry faalt). Antwoorden van de gateway zelf dragen een wildcard `Access-Control-Allow-Origin: *` — het CORS-gedrag van de functie zelf meet je dus alleen met een request mét geldige JWT + `Origin`-header. De 401-van-de-gateway zegt niets over de functie-CORS.
- **CORS-diagnose**: een browserblokkade (ALLOWED_ORIGINS-match ontbreekt) en een serverfout geven in de UI dezelfde generieke foutmelding. Scheiden: `curl -i` met `Origin` + geldige JWT. Komt er géén `access-control-allow-origin` terug → ALLOWED_ORIGINS. Komt er JSON `{code,...}` terug → server-oorzaak.
- **PostgREST kolom-grants**: na `REVOKE SELECT` (tabel) + `GRANT SELECT (kolommen…)` geeft `select=*` én elk select dat de niet-gegrante kolom bevat een **42501 permission denied** — PostgREST laat de kolom dus niet stil weg (strict gedrag). De wél gegranuleerde kolommen leest de rol gewoon.
- **anon vs. authenticated na migratie 014**: `anon` heeft géén SELECT meer op `flow_configs`; `authenticated` kan alleen de 7 niet-geheime kolommen lezen (de token-kolom is write-only via de `flow-config` Edge Function); de service-role leest en schrijft alles.
- **Sessie-JWT's**: ES256 (asymmetrisch), 1 uur geldig; supabase-js refresht automatisch in de browser. Tokens die via tussenliggende tools (chat/kladblok) gekopieerd worden, raken beschadigd — de handtekeningverificatie faalt dan op één karakter. Test-tokens dus altijd rechtstreeks uit de eigen browser (`copy()` in de console) of laat de Network-tab het werk doen.
- **RLS default-deny op statuskolommen**: een tabel zonder UPDATE-policy weigert elke client-update, ook voor een admin. Laat statusovergangen daarom door een Edge Function met de service role (of een SECURITY DEFINER-RPC met eigen autorisatie) uitvoeren; een brede admin-UPDATE-policy geeft admins ook schrijfrecht op alle andere kolommen. Bevestigd in feature 016 (`knowledge_base_documents`, migratie 015/018).
- **Aggregaten zonder N+1**: een view met `WITH (security_invoker = true)` over de RLS-tabellen levert geaggregeerde kaartstatistieken in één PostgREST-query en houdt de RLS van de aanroeper intact. Nieuwe views hebben expliciet `GRANT SELECT` naar `authenticated` nodig; `anon` intrekken.
