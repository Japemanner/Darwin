# Supabase — hypothesen (nog onvoldoende bevestigd)

- **Secrets zijn direct actief zonder herdeploy**: bij de 009-rollout leek een vers gezette `ALLOWED_ORIGINS` direct te werken, maar die sessie is óók herdeployd — het effect is niet geïsoleerd. Bevestiging volgt bij de volgende secret-wijziging zonder redeploy. (1 waarneming)
- **Management-API-token in `.env.local` verloopt stil**: de `SUPABASE_ACCESS_TOKEN` werd afgewezen (401 Invalid access token) zonder dat de CLI of workflow dat eerder signaleerde. Vermoeden: tokens verlopen of zijn geroteerd; verifieer bij volgende CLI/MCP-gebruik en zet verloop-alerts. (1 waarneming)
- **PostgREST `on_conflict` kan geen partiële unieke index targeten**: supabase-js `.upsert(..., { onConflict })` stuurt alleen een kolommenlijst (`?on_conflict=`); PostgreSQL vereist juist het index-predicaat om een partiele unieke index te vinden (index inference), dus verwacht fout 42P10. Workaround in 012: volledige unieke index — NULL's zijn in PG-unieke indexen verschillend (default), dus nullable foreign keys (zoals `feedback_interactions.message_id`) veroorzaken geen conflicten. Bevestiging volgt bij de 012-implementatie/e2e; na bevestiging promoten naar knowledge.md (planning: specs/012-per-answer-feedback/research.md #1). (0 waarnemingen — documentatie-gebaseerd)
